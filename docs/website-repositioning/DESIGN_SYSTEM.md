# Design System — Visual DNA, Interaction Principles, Motion Plan

## Visual DNA to preserve

- Black/white/neutral editorial palette. The base in `style.css` is already correct — do not introduce corporate blue-gradient styling. One accent color exists sitewide (`--color-accent`, `#8c6144` terracotta, driving cursor-hover state and most section accents) — this is the only accent, everywhere, including Capabilities. (A violet/orchid/icy-blue "AI accent" trio was tried for Capabilities' hover/active states in DEC-033 and reverted the same day in DEC-034 — Jaqueline wants black/white/copper only; highlighting something inverts to a white card with black text instead of introducing a new color. Noted here so it isn't reintroduced.)
- Typography: Poppins (body/UI) + Six Caps (display/oversized headline), both via Google Fonts. Large-headline treatment is a core signature.
- A genuinely well-built responsive breakpoint ladder (1537 / 1466 / 1024 / 767 / 479px + a landscape-phone edge case), applied consistently across all CSS partials. **Needs no rebuild** — only verify new sections reuse it rather than introducing ad hoc breakpoints.
- Asymmetry, strong negative space, editorial/fashion influence, a "dark, minimal, slightly experimental" personality.
- Cinematic scrolling and motion, treated as the site's identity, not decoration.

## Interaction principles (non-negotiable for every animation, existing or new)

Every interaction must support one of: **narrative, hierarchy, discovery, comprehension, personality.** Never add animation purely for decoration. Any new interaction must be documented here, in this file, before implementation — including where it appears, its trigger, what moves, duration/behavior, why it improves storytelling or usability, mobile fallback, accessibility consideration, and whether it uses existing libraries or requires something new.

## New interaction — full specs (required before implementation, per the interaction principle above)

### 1. Work-card reveal (replaces the WebGL grid-fit effect)
1. **Where**: `work.html`, the 5 flagship case cards.
2. **Trigger**: scroll-into-view (once) for the initial reveal; mouse-hover (desktop) for the secondary state.
3. **What moves/changes**: on scroll-entry, each card's title and framing line fade/slide up once (ScrollTrigger `toggleActions`, one-time — not the removed continuous-scrub `.has-opacity`); on hover, a restrained image/visual crop reveals behind the text via a CSS `clip-path` or opacity transition. No WebGL, no shader.
4. **Duration/behavior**: ~400–600ms ease-out for entry reveal; ~250ms for hover crossfade.
5. **Why**: preserves the "editorial card, not template tile" feel while removing a heavy, single-purpose WebGL dependency that no longer matches the new card layout — cuts JS payload, aligned with the performance priority.
6. **Mobile fallback**: no hover state on touch — image is either always partially visible or revealed on tap/focus; no content is hover-gated.
7. **Accessibility**: on touch/keyboard, the image reveal happens on focus/tap, never hidden behind hover-only — satisfies "no critical content should depend exclusively on hover."
8. **Library**: existing GSAP/ScrollTrigger already in the stack — no new dependency.

### 2. Repurposed keyword ticker
1. **Where**: Home, directly under the Hero.
2. **Trigger**: scroll-scrubbed, same mechanism as the current moving-gallery marquee.
3. **What moves**: a horizontal strip of positioning keywords/domains ("Enterprise Transformation · Digital Products · Decision Intelligence · AI-enabled Workflows · Customer Data") scrolls continuously, tied to scroll position.
4. **Duration/behavior**: continuous, scroll-position-linked — matches existing marquee behavior, no new timing logic. Pinned scroll range tuned down from `window.innerHeight * 3` to `window.innerHeight * 1` (DEC-030) — the original 3-viewport-height range made the reveal feel like the user had to keep scrolling in place rather than one continuous motion; the per-item stagger/duration values are unchanged, only the pixel range the scrubbed timeline maps onto.
5. **Why**: gives the hero's supporting line room to breathe while reinforcing the 5-domain positioning kinetically, without duplicating the Capabilities section's language wholesale.
6. **Mobile fallback**: same scroll-scrub mechanism already works at narrow breakpoints — no special-casing needed.
7. **Accessibility**: real text content, readable by screen readers if `aria-hidden` isn't applied; add `aria-hidden="true"` only if the same keyword list already appears as static text elsewhere on the page.
8. **Library**: existing GSAP/ScrollTrigger — no new dependency.

### 5. "Intersection" motif (Home, Point of View)
1. **Where**: Home (`index.html`), Point of View section — next to/below the promoted "Building at the intersection of business and technology" headline.
2. **Trigger**: continuous, non-scroll-linked idle animation (renders and animates as soon as the section is in the DOM; not tied to scroll position).
3. **What moves/changes**: a small inline SVG of two overlapping accent-stroked circles (`.pov-mark`) — each circle drifts a few pixels horizontally in opposing directions on a slow loop, so the overlap ("intersection") area subtly breathes rather than sitting static.
4. **Duration/behavior**: ~7s ease-in-out, infinite, alternating direction per circle.
5. **Why**: a literal, original graphic reinforcement of the section's actual thesis (two domains meeting), not decorative filler — satisfies the standing "every interaction must serve narrative/hierarchy/discovery/comprehension/personality" principle via comprehension + personality. Also gives Point of View its own small piece of visual identity, echoing the fine-line-art language already established by the Home signature section's dot field.
6. **Mobile fallback**: renders in-flow (not absolutely positioned), so it stacks naturally under the headline at every breakpoint — no special-casing needed. Same idle animation at all sizes.
7. **Accessibility**: `aria-hidden="true"` (purely decorative graphic, the headline text already carries the meaning); gated behind `prefers-reduced-motion: reduce` (pure CSS, no JS).
8. **Library**: inline SVG + CSS `@keyframes` — no new dependency.

### 6. Capabilities editorial bento grid (Home) — revised twice: supersedes the horizontal-strip version (DEC-032 → DEC-033), then the AI-accent color scheme (DEC-033 → DEC-034)
1. **Where**: Home (`index.html`), Capabilities section.
2. **Trigger**: (a) entrance — see interaction spec 7 below (sitewide `.has-animation`/`.has-mask-fill` for the heading, a scroll-scrubbed descent for the cards); (b) click/tap or Enter/Space on a card, a nav-rail dot, or the prev/next arrows — swaps which card is "featured"; (c) continuous mouse-driven parallax on each card's index/icon while hovering; (d) a continuous, non-interactive ambient 3D wave-mesh behind the whole section.
3. **What moves/changes**: 5 cards sit in an asymmetric 3-column/2-row CSS Grid, one tall "featured" card in the center (larger index/title, untruncated description/tags, **inverted to a white background with black text** — the section's one deliberate high-contrast moment, no new color) and 4 compact cards (2-line-clamped copy, copper `--color-accent` index/hover/divider). Clicking a compact card swaps its slot with the featured one — GSAP Flip animates every card's position/size smoothly. Hovering a card lifts/scales it slightly, dims its siblings, and turns its divider/border copper. Behind the grid, a Three.js `THREE.Points` mesh (~5,400 points on a 90×60 grid) renders an undulating 3D surface in warm copper/bronze/gold tones, vertex-displaced by simplex noise + sine waves, with camera/wave response to cursor position and distance fog fading the far edges to black.
4. **Duration/behavior**: Flip swap ~700ms `power3.inOut`; hover transforms ~350ms; divider fill ~500ms; the wave mesh animates continuously at a slow, organic pace (noise frequency tuned so it reads as "breathing," not water or a spinner).
5. **Why**: requested directly — an "editorial-tech" bento composition with a changeable protagonist card, inspired by (not copied from) the Lando Norris/OFF+Brand site's interaction philosophy, and a "data art" 3D particle surface as the section's signature visual. GSAP Flip and Three.js are both already loaded/used elsewhere in this codebase (hero Flip; Three.js is on `TECHNICAL_STANDARDS.md`'s approved-libraries list for its now-being-replaced grid-fit effect) — reusing them here is not a new dependency. The color scheme was deliberately pulled back from an initial violet/orchid/icy-blue "AI accent" trio (DEC-033) to black/white/copper only (DEC-034) — Jaqueline's call; the featured state communicates emphasis via an inversion (white card/black text), not a new hue.
6. **Mobile fallback** (≤767px): the bento is not reproduced at narrow widths — cards stack in a single column as a tap-to-expand accordion (only one open at a time), described/tagged content revealing via a max-height transition. Same click handler branches on `matchMedia('(max-width: 767px)')` to pick accordion-toggle vs. featured-swap behavior. The wave mesh keeps rendering behind the stacked cards at every width (canvas resizes with the section).
7. **Accessibility**: each card's interactive surface is `role="button" tabindex="0" aria-expanded` with click **and** keydown (Enter/Space) handling — the project's own established pattern for custom interactive elements (see the hamburger-menu row above); nav-rail dots are real `<button role="tab" aria-selected">` elements; cursor parallax and the wave mesh's cursor response are both skipped under `prefers-reduced-motion` and on coarse/touch pointers, and the wave mesh renders exactly one static frame (no RAF loop) under `prefers-reduced-motion` rather than animating; description/tags stay in the DOM at full length always (never hidden from assistive tech), only visually clamped via CSS in the non-featured/collapsed state.
8. **Library**: existing GSAP + the already-registered Flip plugin for the layout swap; existing Three.js (r128, already loaded sitewide) + hand-written GLSL vertex/fragment shaders for the wave mesh — no new dependency either way; vanilla JS for click/hover/keyboard handling. The wave mesh's WebGL context/render loop is disposed via `js/scripts.js`'s `CleanupBeforeAjax()` so it doesn't keep running after the AJAX page-transition system swaps this page's content out.

### 7. Capabilities entrance (Home) — revised three times: replaces the bespoke scramble/fly-in version (DEC-035 → DEC-036), made dramatic/pinned (DEC-036 → DEC-037), then fixed the pin's empty-space problem alongside a layout change (DEC-037 → DEC-038)
1. **Where**: Home (`index.html`), Capabilities section.
2. **Trigger**: (a) eyebrow/title/statement/taxonomy use the sitewide one-time scroll-into-view defaults — `.has-animation` (fade + translateY) and `.has-mask-fill` (word-mask reveal) on the title, the same mechanism as every other section heading including Point of View's promoted statement; (b) the 5 bento cards, on desktop, **pin the whole section** (`.cap2-shell`) for one viewport-height of scroll (`start: 'top top'`, matching this page's other pins) while a scrubbed timeline cascades them in. On mobile (device-detected via the sitewide `isMobile()`, not just viewport width) there's no pin — each card just settles in via a normal (non-scrubbed) `ScrollTrigger` as it's scrolled to.
3. **What moves/changes**: cards start ~65vh above their resting position, scaled to 0.88 and transparent. On desktop, while the section is pinned, each card animates in on its own slice of the timeline (`i * 0.35` offset, 1 unit duration each) so they arrive one at a time in sequence rather than as one blurred simultaneous mass, scrubbed 1:1 with scroll position within the pinned range. On mobile, each card just fades/settles to resting state without the large travel distance being tied to a pin (still scroll-triggered, just not scrubbed or pinned).
4. **Duration/behavior**: desktop — no fixed duration, scrub-driven across the pinned scroll distance (`power2.out` per-card ease within the scrubbed timeline); mobile — ~0.6s per card, `power2.out`, on scroll-enter.
5. **Why**: the previous version (DEC-036, a short non-pinned scrub over a small pixel range with a 90px travel) was reported as barely noticeable on a fast scroll — the trigger's start/end range could pass in a single scroll flick with the rest of the page changing simultaneously, making it easy to miss entirely. Jaqueline asked for the same level of visual drama as this codebase's dormant `.move-thumbs-wrapper` "Recognitions" gallery effect. That mechanism's actual structure (two DOM states, GSAP Flip swapping each thumbnail from a scattered intro layout into a final grid, per-thumbnail `data-start`/`data-stop` scroll offsets) is built for repositioning photos between two different layouts and doesn't fit 5 text cards that don't change position on entry — so this reuses its *underlying technique* (a large, scroll-scrubbed transformation, `scrub: true`) plus this page's own existing pin convention, rather than replicating the two-state thumbnail-swap structure. Pinning is what actually solves "invisible on fast scroll," since it holds the section in view for a fixed scroll distance regardless of scroll speed. The DEC-037 version pinned at `start: 'top 80%'`, which froze the section while it was still mostly below the viewport — leaving a tall empty gap above it for the whole pinned duration, since the previous section had already scrolled out of view. Fixed by (a) pinning at `'top top'` instead, so the section already fills the viewport the moment it freezes, and (b) moving the title/eyebrow out of a narrow side column into a horizontal band above the full-width card grid (`.cap2-intro-left`/`.cap2-intro-right`), so the pinned frame is genuinely full of content rather than a tall column next to empty space. Pin duration was also trimmed from 1.3 to 1.0 viewport-heights now that the frame is better composed.
6. **Mobile fallback**: no pin — a pinned section reads as "stuck" on a touch device, and the ticker/`.pinned-element` mechanisms already elsewhere on this page make the same exception. Cards still animate in, just via a simpler non-scrubbed reveal.
7. **Accessibility**: gated behind `prefers-reduced-motion` (both the desktop pinned-scrub and the mobile reveal are skipped; cards render at rest immediately via the CSS media-query override) — required for the desktop path since it's genuinely scroll-scrubbed motion, per `DESIGN_SYSTEM.md`'s own accessibility principles ("`prefers-reduced-motion` must gate ... all ScrollTrigger-scrubbed motion"); applied consistently to the mobile path too even though it isn't scrubbed, so reduced-motion users get one predictable behavior (immediate, no motion) regardless of device.
8. **Library**: existing GSAP timeline + ScrollTrigger (already loaded, `pin` is a standard ScrollTrigger option already used elsewhere on this page) — no new dependency.

### 8. Selected Work "suspended dossier" (Home) — revised three times: replaces the editorial-index-list version (DEC-040 → DEC-041), then the "case files" tab version (DEC-041/042 → DEC-043), then split the hover reveal out of the card (DEC-043 → DEC-044)
1. **Where**: Home (`index.html`), Selected Work section.
2. **Trigger**: (a) one-time scroll-into-view entrance, staggered per card; (b) pointer hover/move and keyboard focus/blur on a card.
3. **What moves/changes**: the 5 case studies render as scattered mega-cards (`.work-file`, width driven by the shared `--work-card-w` token) freely positioned by percentage `left`/`top` inside a full-bleed black canvas (`.work-canvas`, on a light `.work-frame` background so the black canvas itself reads as a distinct "stage"). Composition is a two-stack diagonal descent — cards 01/03/05 stacked upper-left to lower-left, 02/04 upper-right to lower-right — each with a fixed base rotation (±7–13deg) and `z-index` depth, deliberately overflowing the canvas edges into the surrounding light frame (`overflow: visible`). A faint centered "PROJECT ARCHIVE" marker sits in the empty middle. The card face itself carries only two pieces of copy — the work-tag and a large `.work-file-title` (fluid clamp reaching 4.6rem) — nothing else. Each card is 3 layered elements: `.work-file` (outer anchor — owns base position/rotation only, never touched by JS) → `.work-file-motion` (owns only pointer-follow transform, driven by JS-set CSS custom properties) → `.work-file-content` (rigid surface — background, border, tag + title; never transformed). The description + "View case study →" live in a separate `.work-file-reveal` element, a plain sibling immediately after the card in markup (not layered on top of it): on hover/focus it fades/slides in from the side of the card facing the canvas center (`data-side="right"` for the left-hand stack, `data-side="left"` for the right-hand stack), landing in the empty middle void the composition leaves for exactly this purpose. Its horizontal offset is computed as half the card's width (`--work-card-w`) plus half the reveal's own width (`--work-reveal-w`) plus a fixed gap — both widths read from shared tokens so the clearance can never drift out of sync with the actual rendered card size the way a hand-tuned pixel offset would — and it sits at a lower `z-index` than every card depth, so if a rotated corner ever still reached into that space the card's own solid surface would win, never the reveal text. Sibling cards also dim to 0.78 opacity via `.work-scene:has(.work-file.is-active)`. Hovering additionally drives a bounded, lerped cursor-follow on the card itself: it tilts/lifts toward the pointer (translate + scale via `.work-file-motion`'s custom properties, sine-based edge resistance so it never overshoots) without ever straightening its base rotation — physics are added on top of the fixed pose, not a replacement for it.
4. **Duration/behavior**: entrance is a CSS `transition` (not GSAP-tweened, since the resting state already carries `translate(-50%,-50%) rotateZ(...)` — animating that with GSAP would fight the base transform), ~0.9s `cubic-bezier(0.16,1,0.3,1)`, staggered per card via `transition-delay`. Hover-follow is a manual `requestAnimationFrame` loop lerping current→target position at 0.08/frame, started on `pointerenter` and stopped once settled (not left running indefinitely). The reveal's fade/slide and the card's material change are plain CSS transitions, ~350–400ms ease.
5. **Why**: Jaqueline sent a fully detailed technical brief for a "suspended dossier" 3D spatial composition — scattered, overlapping, edge-overflowing cards evoking documents pinned to a board, replacing the more literal "file tab" metaphor (DEC-041/042). The brief explicitly required: cursor-follow must never fight or replace the base rotation/position (hence the 3-layer split — outer anchor / motion wrapper / rigid content, so JS only ever touches an element with no other transform source); movement must be weighted/lerped with edge resistance, not directly mapped 1:1 to pointer position; and text must stay rigid (living in the untouched `.work-file-content` layer) even while the card tilts. DEC-044 then pulled the description/CTA out of the card face entirely — she wanted the card limited to exactly two texts (tag + a much larger title) with the hover detail projecting outward into the void the composition already leaves empty for that reason, rather than expanding inside the card as before.
6. **Mobile fallback** (≤767px): the scattered/overlapping composition is explicitly **not** reused — `.work-scene` becomes a static vertical flex stack (cards `position: relative`, slight negative margin for a shingled overlap, fixed per-card `--mobile-rotate` instead of the desktop base rotation), and there is no pointer-follow physics at all (no hover on touch). There's no horizontal void to project into on a phone-width stack, so `.work-file-reveal` switches from an absolutely-positioned side panel to a `max-height`-collapsible block sitting directly below its card (`position: static`, in normal document flow as the card's next sibling), visually reattaching to it as a single unit. Interaction is tap-to-reveal-then-navigate: first tap on a card adds `.is-active` (expanding the reveal below it) and calls `preventDefault()` **and** `stopImmediatePropagation()` on the click — required because the site's own ajax-link/page-transition handlers (`js/common.js`) are bound to the same `<a>` element (and via delegation on `#main`) and start the page transition unconditionally on click, ignoring `preventDefault()` alone; a second tap (now `.is-active`) lets the click continue through to navigate normally.
7. **Accessibility**: each card is a real `<a>` (native focus/keyboard/Enter support); `focus`/`blur` drive the same `.is-active` state as pointer hover, so the reveal shows for keyboard users too. The one-time entrance reveal is unguarded under `prefers-reduced-motion` (matches the sitewide `.has-animation` precedent), but the continuous cursor-follow physics are fully gated — under reduced motion, `.work-file-motion`'s transform is forced to `none` and the RAF loop never starts, while hover/focus's material-change and detail-reveal (a one-time state toggle, not continuous motion) still work normally.
8. **Library**: pure CSS transitions/custom-properties plus a small hand-rolled `requestAnimationFrame` lerp loop (no GSAP tween on the motion layer, to avoid the transform-decomposition conflict described above); a single `ScrollTrigger.create({ once: true })` fires the entrance. No Three.js/WebGL for this section (unlike Capabilities) per the brief's explicit performance constraint — no new dependency either way.

8. **Library**: existing GSAP/ScrollTrigger — the entrance reveal reuses `.has-animation` as-is. The image parallax intentionally does **not** reuse the vendor `.has-parallax` mechanism: that class is also targeted by an unrelated mobile-only fix elsewhere in `js/common.js` (`isMobile()` block, `$('.smooth-scroll main, .has-parallax, nav, ...').css({'height': winHeight})`) that forces matching elements to exactly `window.innerHeight` — correct for that block's full-viewport background use cases, but it silently broke this card's `aspect-ratio` sizing on mobile when tried. Fixed with a small, purpose-built GSAP/ScrollTrigger block scoped to `.signature-card` instead (same fromTo recipe, own trigger) — no new dependency, no vendor code touched. See `DECISIONS.md`.

## Accessibility principles (standing, applies sitewide)

- `prefers-reduced-motion` must gate: the custom cursor, all ScrollTrigger-scrubbed motion, the AJAX transition cover-layer fade, and the preloader.
- No critical content may depend exclusively on hover — every hover-triggered reveal needs a focus/tap-triggered equivalent.
- Visible `:focus-visible` styles are required sitewide (currently absent anywhere in the CSS, combined with a global `user-select: none` — a real, confirmed gap).
- Keyboard operability is required for the hamburger menu and any custom interactive component (`role`, `tabindex`, `aria-expanded`/`aria-controls` as appropriate, keydown handling alongside click).
- Text must be fully legible at rest — no interaction may leave positioning-critical copy at reduced opacity/contrast as a resting state (this is why `.has-opacity` is being removed/replaced, not just refined).
- Semantic heading structure: one `<h1>` per page, no skipped levels.
- Descriptive `alt` text on every meaningful image; decorative images get `alt=""` deliberately, not by omission.
